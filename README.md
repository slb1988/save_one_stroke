## 怎么玩

1. 看本关试坐条件，在**本关亮色标明的画区**按住鼠标 / 一根手指画一条连续线；入门默认椅面以下，部分变种开放上方或只准修上面。
2. 墨水按实际轨迹长度扣除。一笔可以拐弯；用尽会自动收笔。靠近木椅水平面、地板或台阶顶面的端点有 10 个画布单位的轻微吸附，吸附仍计费。
3. 碰到木椅的线会焊成硬支架；没有接上的线是自由落体，绝不钉在空气里。要把重量传到实心表面，或接上本关明确标出的墙面金环；不能钻入实体、猫区或落球出生圈。
4. 抬笔后点击「请阿稳试坐」，观察 5 秒。实际接触点显示绿色箭头，重量投影也可观察。
5. 随时清除 / 立即重试，不扣命。两级提示不扣星，任意选关；成功后可继续或挑战少墨水纪录。

通过即至少一星；用墨 ≤ 本关三星目标获三星，其余 ≤ 墨水总量 91% 获两星。成绩和音效设置仅保存在本机 `localStorage`，拒绝存储时仍可正常玩。

键盘：`Tab` 选中画板，方向键移动笔尖，空格落笔 / 抬笔，`Shift` 慢移；`R` 重画，`Enter` 试坐。画板外可正常触屏滚动。音效默认关闭，可手动开启。

### 动态添加，不手写目录

1. 在自己的 `levels/<namespace>/<slug>.json` 增加 v3 关卡，填写稳定id与 progression；在 `tests/cases/<namespace>/` 配合法解和失败例。
2. 用 `npm start` 开发服务时，点击「刷新目录」即可发现新增文件，无需重启；坏文件显示路径并隔离，不破坏当前笔画、试坐、成绩或导入库。
3. 新类型放在 `js/modules/<namespace>/<slug>.js` 自注册；场景配方与模块接口见 **[docs/MODULES.md](docs/MODULES.md)**，不用编辑通用主循环或中心 imports。
4. 纯静态发布前运行 `npm run content:build`，然后 `npm run content:check`，一起发布文件与生成索引。Nginx 不扫描目录，刷新不会从 GitHub 拉未发布内容，也不需要生产 Node 服务。

本轮未提交、推送或部署。难度是作者标注，合法解不等于趣味性已经由玩家确认。

## 单关文件与序列化

完整坐标/字段规则、引擎机制边界、可直接使用的 JSON 示例、离线流程与 LLM 提示见 **[docs/LEVEL_FORMAT.md](docs/LEVEL_FORMAT.md)**；机器可读格式见 **[v1 Schema](schemas/level-v1.schema.json)** / **[v2 规则变种 Schema](schemas/level-v2.schema.json)** / **[v3 模块组合 Schema](schemas/level-v3.schema.json)**。

点击「导入 / 本地关卡」导入 UTF-8 JSON：校验成功后自动存入本机，刷新后可从本地列表继续玩。最多12份、每份64 KiB；同 id 不覆盖内置关，同内容去重，坏文件/保存失败不会切换关卡或覆盖旧存档。移除本地存档需二次点击确认。

`levels/manifest.json` 是自动生成的发布目录；开发服务用同一个发现器实时返回它。顺序由每关 progression 决定，旧关的编排放在 `levels/legacy.progression.json`；没有 id+1 或必须连续编号的限制。

点击画板标题右侧 **「↓ 保存关卡」**，可下载本关的完整 JSON；内容与项目中的原文件无损一致，包含：

| 字段 | 含义 |
| --- | --- |
| `format` / `version` | `save-one-stroke-level` / `1`、`2`或`3`；旧关保持原规则 |
| `id` / `chapter` | v1/v2数字id不变；v3为namespace/name和自定义分组 |
| `scene` / `progression` / `drawArea` | v3的模块实例、编排和可选画区；替代下列旧版几何与mechanics字段 |
| `title`、`brief`、`condition` 等 | 标题、规则及试坐反馈文字 |
| `ink` / `gold` | 墨水上限、三星用墨目标 |
| `chair[]` | 木椅矩形 `{x,y,w,h,kind}`，第一块必须是 `seat` |
| `terrain[]` | 实际承重矩形 `{x,y,w,h}`，不需要用图片推断 |
| `load` | 人的 `x`、`mass`，以及可选抱猫重量 |
| `forbidden` / `forbiddenZones[]` | 单个 / 多个猫区矩形 |
| `forces[]` | 可选定时外力：`start/end` 毫秒、`fx/fy`、施力点 `at:{x,y}`、显示 `label` |
| `mechanics` | v2必填：`temporaryTerrain`、`anchors`、`gravity`、`drops`规则数组及可选`drawTop/drawBottom`画区 |
| `hint[]` / `labels[]` / `gap` | 提示、画板标注、空洞警示；空洞能否承重仍由 terrain 决定 |

坐标系固定为 **720×480，左上角为原点，y 向下**。JSON 只存关卡，不存执行函数、物理引擎对象或参考答案；玩家成绩仍在 localStorage，避免把关卡与游玩状态混在一起。

可直接导入的例子：`docs/examples/level.json`（v1）、`docs/examples/variant.json`（v2）、`levels/lab/up-we-go.json`（v3）。加载时统一验证格式与参数；v3导出保留配方而不是展开缓存。详细旧版字段和v3差异见 LEVEL_FORMAT.md，不要混用。当前不扩展关卡编辑器或在线模型调用。导出的文件不含玩家解答或成绩；跨设备请发 JSON，而不是只发 `#local=...` 本地引用链接。

## 物理模型与边界

- 本地 **Matter.js 0.20.0**；笔画由真实有质量的线段 / 端点碰撞体组成，木椅与接上的笔画为复合刚体。形状、落点、载荷和障碍都参与计算，不识别预设答案。
- 阿稳是抱住椅子的刚性试坐假人，其重心和重量计入复合刚体；不是独立布娃娃。木头和墨水在本版不会断裂，整个结构会滑动、旋转、翻倒。
- 复合结构用平行轴定理补足转动惯量，避免细长结构不真实的碰撞发射。模拟固定为 120 Hz，浏览器与测试使用完全相同的 `physics.js`。
- 任意时刻倾斜超过 24°、座面下坠超过 65 个单位、移出试坐范围或碰猫，失败不可逆。到 5 秒时还须倾斜 <10°、连续稳定至少 0.7 秒且具有实际承重接触或木椅的有效金环铰接，才会通过。可观察轻微晃动，不是按“碰到两个点”直接宣布成功。
- v2 临时地形会从物理世界移除；金环创建可转动的零长度约束；重力时序改写整个世界方向；落球到时才创建动态圆球。预告、图形与失败原因都读取机制数据，不按关号判定，不强行设静止或识别答案。
- 定时外力通过 Matter 的 `Body.applyForce` 在指定载荷点逐帧施加，真的产生滑动和转矩；不是根据某个画法触发的预设翻倒动画。第 7 关无风时能坐稳的单侧支架，在反向风中会翻倒。
- 轨迹有 1.2 单位的几何简化以降低碰撞体数量，但墨水按原轨迹计费；原轨迹和简化轨迹都会做障碍检查。
- 离开后台标签或打开玩法窗口时暂停试坐，不因掉帧跳过物理过程。

## 验收

无需安装任何依赖即可离线检查单关（不提供 cases 时只代表格式通过，不代表可解）：

```sh
npm run level:validate -- docs/examples/level.json --json
npm run level:validate -- docs/examples/level.json --cases docs/examples/level.cases.json --json
npm run level:validate -- docs/examples/variant.json --cases docs/examples/variant.cases.json --json
```

工程测试需要开发依赖（AJV 只用于 Schema 测试，Playwright 只用于浏览器验收；游戏运行不需要它们）：

```sh
npm ci --cache .cache/npm
npm test
npm run content:check
# 模块组合专项；浏览器脚本需先启动 npm start，可用 GAME_URL 指定地址
npm run test:content
npm run test:content:browser
# 第三轮只验新变种，不重跑旧关矩阵
npm run test:variants
npm run test:variants:browser
# 第二轮的格式 / 本地导入专项入口仍保留
npm run test:format
npm run test:import
```

原有核心测试保留：每关各有一个合法解、一个合法但失败的画法、一个不同路径的合法解；还覆盖悬空自由落体、空洞因果、改变重心、猫区线段穿越、墨水限额、吸附、坐满五秒、端点容错、失败不可逆、JSON 无损往返、文件格式校验、定时反向风的因果和双猫禁区。

第二轮另有 **9 项格式/存储/离线入口测试**，覆盖按版本选择的 Schema、坏文件、配额、id隔离和本地恢复；`test:import` 聚焦原生鼠标导入 → 试坐 → JSON 导出，验证刷新恢复、错误文件和390px布局，不重复完整矩阵。

第三轮 `test:variants` 检查新四关的合法解、另一条自由解、朴素失败、JSON往返和真实机制事件；另将新机制去掉做反事实检查，证明失败确实由规则变化引起。`test:variants:browser` 用原生鼠标验证四种变化及落球失败/快重试，并走通 v2 导入试玩导出和390px布局。

原有全关浏览器入口保留（本轮不重跑旧矩阵，仅开发测试需要 Playwright）：

```sh
npm ci --cache .cache/npm
npm run test:browser
```

测试优先使用本机 Chrome / Edge / Chromium，也可用 `BROWSER_PATH` 指定可执行文件。使用隔离浏览器和项目内临时目录，不读写用户浏览器资料；服务未启动时会临时启动并在测试结束后关闭。

## 文件

- `scripts/validate-level.cjs`：离线格式及同引擎样例验证入口。
- `js/physics.js`：通用几何规则、刚体构造和试坐判定。
- `js/render.js` / `js/render-art.js`：Canvas分层合成、共用画笔和人物；元素自己绘制外观。
