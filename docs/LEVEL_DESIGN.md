# 一笔关卡设计方法（沉淀自三批派生试验）

给后续作者的短小可复用方法，不是关卡清单或验收报告。单关证据、参数与返工细节留在各实验目录（`.local/level-variants-0*`），此处只留方法。用户/策划做趣味筛选，作者不打趣味分。

## 反馈事实（先说清证据边界）

- 第二批 5 个配置（配重球/挂点松手/双平台接力/重力回程/弹性导流）获用户原话正反馈：“新的这几个确实有意思多了”。这是对**该批整体**的一次反馈，不等于每关单独有趣，不证明任意人群都喜欢；第一批与作者自评的“可能有趣”没有此类证据。
- 本批（第三批）起，把“作者推测”与“用户反馈”分开标注：以下方法里只有设计假设，具体关卡是否留用由人判断。

## 可复用方法

1. **角色反转**：把障碍改成资源——落球可以当配重（V1）、风可以当便车（W1）、球可以去按开关（W3）。反过来也成立：资源（地板、挂点、挡板）按时刻撤走就是新风险。
2. **关系/时序变化**：不换题面换关系——力的方向分段换向、支撑按时撤走、挂点到点松手、平台单程移动、第二个球面对被撤走后的新路。一笔不变，世界在变。
3. **一笔多职**：同一条连续线承担两个真实职责（既是腿又是挡板；既悬挂又是落地架）。失败样例按“漏掉哪一职”分别设计，可读性比难度重要。
4. **可观察因果**：让玩家看见现象——球被接住、环松开变灰、平台到站、反弹路径、感应区被触发。因果藏在代码里就不是题。
5. **保留替代解**：合法替代解（绕开题意的右腿、V形兜）记录给策划，不自动封死；它还可以升格为下一道题的主题（V形兜→收纳箱）。
6. **同一数据驱动物理与展示**：关卡 JSON 既跑仿真又跑页面，预览图从实际 JSON 生成，不手绘第二套几何。
7. **对照只服务因果**：对照组用来隔离一个变量（无球/不撤/不释放/低弹性）；有限探针没找到合法失败样例时，写“未找到”，不写“不存在”。

## 能力边界约定

- 原成败阈值（5 秒、倾角、稳定窗口、危险区）不改；新能力以“可选参数、安全默认、闭合校验、事件预告、重试隔离、回归测试”成套出现。
- 真实刚体优先：触发用真实接触，不用定时冒充；预告与视觉状态与实际物理一致。
